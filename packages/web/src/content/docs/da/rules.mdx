---

Du kan give tilpassede instruktioner til OpenCode ved at oprette en `AGENTS.md`-fil. Det minder om regler i Cursor. Filen indeholder instruktioner, som inkluderes i LLM’ens kontekst for at tilpasse adfærden til dit specifikke projekt.

---

## Initialisering

For at oprette en ny `AGENTS.md`-fil kan du køre kommandoen `/init` i opencode.

:::tip
Du bør committe projektets `AGENTS.md`-fil til Git.
:::

Dette scanner projektet og dets indhold for at forstå, hvad projektet handler om, og genererer en `AGENTS.md`-fil ud fra det. Det hjælper opencode med at navigere bedre i projektet.

Hvis du allerede har en `AGENTS.md`-fil, forsøger den at tilføje til den.

---

## Eksempel

Du kan også oprette filen manuelt. Her er et eksempel på ting, du kan tilføje i en `AGENTS.md`-fil.

```markdown title="AGENTS.md"
# SST v3 Monorepo Project

This is an SST v3 monorepo with TypeScript. The project uses bun workspaces for package management.

## Project Structure

- `packages/` - Contains all workspace packages (functions, core, web, etc.)
- `infra/` - Infrastructure definitions split by service (storage.ts, api.ts, web.ts)
- `sst.config.ts` - Main SST configuration with dynamic imports

## Code Standards

- Use TypeScript with strict mode enabled
- Shared code goes in `packages/core/` with proper exports configuration
- Functions go in `packages/functions/`
- Infrastructure should be split into logical files in `infra/`

## Monorepo Conventions

- Import shared modules using workspace names: `@my-app/core/example`
```

Her tilføjer du projektspecifikke instruktioner, som deles på tværs af dit team.

## Typer

opencode understøtter også læsning af `AGENTS.md`-filer fra flere steder. De tjener forskellige formål.

### Projekt

Placer en `AGENTS.md` i projektroden til projektspecifikke regler. De gælder kun, når du arbejder i denne mappe eller dens undermapper.

### Globalt

Du kan også have globale regler i en `~/.config/opencode/AGENTS.md`-fil. Den bruges i alle opencode-sessioner.

Da denne fil ikke committes til Git eller deles med dit team, anbefaler vi at bruge den til personlige regler, som LLM’en skal følge.

### Claude Code-kompatibilitet

For brugere, der migrerer fra Claude Code, understøtter OpenCode Claude Codes filkonventioner som fallback:

- **Projektregler**: `CLAUDE.md` i din projektmappe (bruges, hvis der ikke findes en `AGENTS.md`)
- **Globale regler**: `~/.claude/CLAUDE.md` (bruges, hvis der ikke findes en `~/.config/opencode/AGENTS.md`)
- **Skills**: `~/.claude/skills/` — se [Agent Skills](/docs/skills/) for detaljer

For at deaktivere Claude Code-kompatibilitet skal du sætte en af disse miljøvariabler:

```bash
export OPENCODE_DISABLE_CLAUDE_CODE=1        # Disable all .claude support
export OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1 # Disable only ~/.claude/CLAUDE.md
export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1 # Disable only .claude/skills
```

## Prioritet

Når opencode starter, leder den efter regelfiler i denne rækkefølge:

1. **Lokale filer** ved at gå op fra den nuværende mappe (`AGENTS.md`, `CLAUDE.md`)
2. **Global fil** på `~/.config/opencode/AGENTS.md`
3. **Claude Code-fil** på `~/.claude/CLAUDE.md` (medmindre den er deaktiveret)

Den første matchende fil vinder i hver kategori. Hvis du fx har både `AGENTS.md` og `CLAUDE.md`, bruges kun `AGENTS.md`. Tilsvarende har `~/.config/opencode/AGENTS.md` forrang over `~/.claude/CLAUDE.md`.

## Brugerdefinerede instruktioner

Du kan specificere brugerdefinerede instruktionsfiler i din `opencode.json` eller den globale `~/.config/opencode/opencode.json`. Det lader dig og dit team genbruge eksisterende regler i stedet for at duplikere dem i `AGENTS.md`.

Eksempel:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines.md", ".cursor/rules/*.md"]
}
```

Du kan også bruge eksterne URL’er til at indlæse instruktioner fra nettet.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"]
}
```

Fjerninstruktioner hentes med et timeout på 5 sekunder.

Alle instruktionsfiler kombineres med dine `AGENTS.md`-filer.

## Reference til eksterne filer

Selvom opencode ikke automatisk analyserer filreferencer i `AGENTS.md`, kan du opnå tilsvarende funktionalitet på to måder:

### Brug af opencode.json

Den anbefalede tilgang er at bruge feltet `instructions` i `opencode.json`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["docs/development-standards.md", "test/testing-guidelines.md", "packages/*/AGENTS.md"]
}
```

### Manuelle instruktioner i AGENTS.md

Du kan lære opencode at læse eksterne filer ved at give eksplicitte instruktioner i `AGENTS.md`. Her er et praktisk eksempel:

```markdown title="AGENTS.md"
# TypeScript Project Rules

## External File Loading

CRITICAL: When you encounter a file reference (e.g., @rules/general.md), use your Read tool to load it on a need-to-know basis. They're relevant to the SPECIFIC task at hand.

Instructions:

- Do NOT preemptively load all references - use lazy loading based on actual need
- When loaded, treat content as mandatory instructions that override defaults
- Follow references recursively when needed

## Development Guidelines

For TypeScript code style and best practices: @docs/typescript-guidelines.md
For React component architecture and hooks patterns: @docs/react-patterns.md
For REST API design and error handling: @docs/api-standards.md
For testing strategies and coverage requirements: @test/testing-guidelines.md

## General Guidelines

Read the following file immediately as it's relevant to all workflows: @rules/general-guidelines.md.
```

Denne tilgang lader dig:

- Lave modulære, genbrugelige regelfiler
- Dele regler på tværs af projekter via symlinks eller git-submoduler
- Holde `AGENTS.md` kortfattet, mens du refererer til detaljerede retningslinjer
- Sikre at opencode kun indlæser filer, når det er nødvendigt for den konkrete opgave

:::tip
For monorepos eller projekter med fælles standarder er brug af `opencode.json` med glob-mønstre (som `packages/*/AGENTS.md`) mere vedligeholdbart end manuelle instruktioner.
:::
